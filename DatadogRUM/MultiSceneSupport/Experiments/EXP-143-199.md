## EXP-143 — External semantic-router mutations and restoration

Status: PARTIAL PASS after FAIL and rejected candidates · backend. Initial
repeated-path restoration and pre-view lifecycle attribution are accepted;
external replacement, rejection, and canonicalization remain.

### Question

Does the experimental iOS 27 semantic `RUMNavigationStack` preserve committed
occurrence semantics when the application's router, rather than a destination
link, replaces or rejects the path, and when the stack restores directly into
repeated equal values?

### Required cases

- programmatic same-type and different-type replacement;
- a router that rejects a proposed path write;
- a router that canonicalizes a proposed write;
- restoration to one route and directly to two equal routes;
- lifecycle work attributed only after the accepted destination occurrence is
  current; and
- no change to native `NavigationLink(value: Route)` matching.

### Acceptance

The application binding remains authoritative. Rejected proposals create no RUM
transition; canonicalized proposals create only the accepted path. Every
materialized repeated path position has a distinct RUM UUID, and a revealed
destination starts fresh before its first lifecycle callback work. Mapper and
backend view/action/Resource inventories must agree, with no automatic duplicate,
error, or crash.

### Preconditions and implementation revision

- Xcode 27.0 (`27A266a`), iPadOS 27 simulator
  `B4E4F039-CA5D-4D04-A904-1D71099BE651`.
- Each attempt proved terminate/uninstall/missing-container before install.
- Native scene `33F68994-4513-4100-B294-A1F5A5A2EE23` was stable through the
  accepted final run.
- The scenario starts the customer path at `[detail-1, detail-1]`, then commits
  `[detail-1]` and `[]`. Its required RUM sequence is D1 -> fresh D2 -> first
  Home, with no hidden Home or automatic view.
- Accepted implementation: `4d64d8a53` (`Harden restored semantic navigation

### Attempts

   published hidden Home H1 before initial top D1. The first pop correctly
   created D2 and the second created H2, but the scenario could not observe a
   first Home after its boundary because H1 had consumed occurrence 1.
2. `semantic-initial-repeat-20260915-fix-a`, session
   `6f5acd00-7718-43f7-820f-97787fbd43d6`: **FAIL**. Gating non-current
   semantic configurations removed hidden Home and every automatic duplicate,
   but the first pop stopped D1 without starting D2. The sole initially
   materialized equal-route boundary retained its removed depth-2 occurrence
   key instead of adopting the surviving depth-1 position.
3. A state-only unit draft constructed two simultaneous materialized claims for
   the restored equal values. It failed because both claims selected the last
   equal position. This construction is **INVALID** as iOS 27 materialized only
   the top destination in both device runs; it was replaced with coverage for
   the one platform-proven materialized claim.
4. The accepted candidate retains each claim while its position survives, but
   rebases a claim when a committed contraction removes that position and the
   same route becomes the new top. Focused state validation passes 4/4,
   including normal sequential equal push/pop and restored-position rebasing.
   Clean device run `semantic-initial-repeat-20260915-fix-b`, session
   `0fad0ffc-6c2d-4614-8a36-cbf03a375dae`, passes all 14 local expectations and
   backend intake. Implementation commit: `f885f9da4`.
5. `semantic-initial-repeat-20260915-fix-c`, session
   `26d85c11-67fb-47ab-88e3-b76fdcf85007`, was a **runtime PASS but rejected
   implementation candidate**. It moved initial ownership ahead of hidden-root
   lifecycle work and passed 20/20 with the correct four views and 43 backend
   events. Source review then found deterministic bootstrap and teardown races:
   the donor generation fence was not total, a same-scene replacement state
   could not adopt the live occurrence, reconnect before queued cleanup could
   swallow a fresh reader, and a donor scene move before descriptor
   reconciliation could strand ownership. Runtime success did not override
   those failures.
6. `semantic-initial-repeat-20260915-fix-d`, session
   `b0944898-77ca-4129-adcd-ad9489285929`, was also a **runtime PASS but rejected
   implementation candidate**. It passed 20/20 and backend intake with 43 events,
   yet successive adversarial callback-order tests found five remaining families:
   a disconnected dormant replacement could not rearm; a previously used donor
   could not regain ownership in the same or another scene; a newer accepted
   generation with its descriptor pending could fence the last proven
   destination; combining donor reuse with disconnect reproduced the strand in
   either reconnect order; and an inactive donor whose local value advanced to
   the newer boundary could no longer reclaim ownership.
7. The final candidate separates the source's validated donor-boundary metadata
   from the state that owns the last proven visible destination. Reader-qualified
   replacement states are preflighted before a live owner is stopped; exact live
   identity is transferred in the same scene, while disconnect or scene migration
   starts one fresh occurrence. Non-reader and stale-generation callbacks cannot
   take those paths. Forty-nine source-order tests cover accepted identity before
   descriptor, multiple and out-of-order donor refreshes, detach/disappear,
   replacement state reuse, queued teardown, both reconnect orders, and scene
   migration. Static adversarial review returned **PASS**. Clean run
   `semantic-initial-repeat-20260915-fix-e-final`, session
   `9a7169ea-d582-4801-82ef-1a73bba6dfb3`, then passed 20/20 locally and in
   backend intake on the exact committed source.

### Conclusion and next boundary

iOS 27 restoration is lazy: the root and current top exist initially, while a
lower equal destination does not. A non-current boundary must lend concrete scene
proof without starting a RUM view, while the source owns the last proven visible
destination until its accepted boundary materializes. Reliable reader mounts may
transfer that ownership or recover it fresh after disconnect; delayed trait,
refresh, detach, and disappear callbacks must remain fenced. This occurrence and
pre-view attribution contract now passes deterministic review, local mapper, and
backend intake. `EXP-143` remains open only for programmatic replacement,
rejected writes, and canonicalized writes; do not infer those results from the
restoration case.
